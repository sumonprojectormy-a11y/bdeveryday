# BD Everyday

Next.js App Router application with the Bengali and English BD Everyday news portal, companion Sites, Supabase-backed newsroom and CMS, and COD ordering. The main edition uses the approved v44 HTML, styles, logo, photos, map, clips, and show/hide behavior through a Next.js Route Handler. The admin interface uses Tailwind CSS. Public news routes, including `/jobs/`, retain their original meanings. Price Comparison is at `/compare`, Jobs & Opportunities at `/opportunities`, and Shop at `/shop`.

## 1. Folder and file tree

See [FILE-TREE.txt](FILE-TREE.txt) for the exact project tree. The ZIP includes every file, including original media and GeoJSON-derived map data. Files in `lib/generated/` are generated by the supplied build and typecheck scripts.

## 2. Database

Run [supabase/schema.sql](supabase/schema.sql) and then [supabase/demo.sql](supabase/demo.sql) in the same project's Supabase SQL Editor. Each file runs as its own transaction and may be replayed. The site ships with 132 bundled articles in each language, including the reviewed evergreen guides. The seed adds the companion records, delivery zones, stock and a newsroom training draft without duplicating or reordering the bundled articles.

The schema creates the private administrator registry, `public.is_admin()`, RLS policies, five newsroom/editorial tables plus staff, the CMS, order records and two storage buckets. Direct public access to the newsroom table is disabled to protect staff email and unpublished records. The public article API projects allowed fields from visible rows. The public storage bucket contains published media selected by administrators. The private bucket contains reader attachments and newsroom photos, served through route guards.

## 3. Backend and authentication

Session cookies are refreshed by the Next.js Proxy. Dashboard and mutations verify the Supabase identity and the administrator registry. The original staff desk grants reporter/editor access by email and restricts reporters to their own unpublished drafts and reviews. Staff must already exist in Supabase Auth. The route handler removes incoming identity headers and applies verified identity internally.

The server uses the Supabase transaction pooler for publication, private submissions, live coverage and COD order transactions. Supabase SSR and Storage handle authenticated dashboard queries and media. Checkout uses server pricing, row locks, stock updates, generated totals and an idempotency key. Public requests never accept SQL or unrestricted table names.

## 4. Public UI

- News, EN edition, article URLs, search and result filtering, saved stories, personalization, country and district map, archive, e-paper, media, reader submissions, live events, SEO and the localized 404 use the original build with Supabase adapters.
- Browser preferences are stored locally as in the reference.
- With no environment variables, the public reference pages and companion demos run in demo mode. Supabase sign-in and production writes activate after setup.
- The shop adds the name, phone and address fields required to create a real COD order in connected mode. The opportunities module links to an official application destination when its record has one.
- Existing source imagery and dynamic stories retain their original source/credit and translated paths. The reference uses an external translation service as a fallback for published articles without authored English text. Use a Translation record for editorially reviewed titles, summaries and body copy.

### Article search visibility

Visible newsroom publications and the bilingual evergreen guides explicitly listed in
`reference/news/worker/published-guides.json` are included in the sitemap. The list applies to
both editions and is validated at build time. Other bundled articles remain accessible at their
existing URLs but are omitted from the sitemap and return `noindex`. Do not block those URLs in
robots.txt: crawlers need to fetch the page to read the directive. A visible newsroom publication
takes precedence if its ID matches a bundled article.

Run `npm run test:article-search` to check both editions, demo directives, and sitemap behavior.

## 5. Administration

`/admin/login` signs in both administrators and newsroom staff. Administrators go to `/admin`. Reporters and editors reach the original newsroom dashboard. The admin sections list, paginate, create, edit, and delete the records supported by each workflow. Reader submissions originate from public forms and orders from checkout, with status and review editing in administration. Nested CMS fields are edited as validated JSON. The Media section uploads images directly to Supabase Storage and gives you a URL to use in the media record. The Articles form has its own publication-gated image upload.

| Section | Configuration |
|---|---|
| Articles | Title, summary, body, author, category, optional district or country, draft/review/published, breaking flag 0/1, optional ISO publication time, optional image. New article IDs may be generated. |
| Staff | Email and role reporter/editor. Owner access is granted through `scripts/grant-admin.mjs`. |
| Live | Create events and updates with their event ID, manage start/end times. Use `/#tool/live-desk` for the start/post/end workflow. |
| Reader message and corrections | Review timestamp and original submission. Publish an article note using the article ID and optional source link. |
| Homepage placement | Use slug `lead`, `secondary`, `picks`, `district`, `probash`, `national`, `guides`, `business`, `sport`, or `education`. Payload is `items`, an ordered array of article IDs. The lead requires a photo. |
| Navigation and copy | Active navigation rows add links in the brand menu. Use `label`, optional `labelEn`, and `href`. Supported copy slugs are `slogan` and `facebook-label`, with `bn` and optional `en` strings. |
| Video | Ordered rows replace the video collection when active records exist. Use `type`, `title`, `duration`, `description`, HTTPS or site-local `src`, and `poster`. The first row is featured. |
| Media and gallery | Media accepts URL, alt/English alt, photographer and optional source and licence. Galleries accept title/English title and ordered pairs of media slug and article ID. With active gallery rows, the photo page uses them. |
| E-paper | Use date as YYYY-MM-DD, edition as morning/evening, and `pages` as an ordered array of category-key arrays. Entries override the matching demo issue. |
| Translation | Use the article ID as slug and enter `title`, `summary`, and `body` in English. |
| Comparison | Category 1–3, name, detail, keywords and a list of offers with merchant, price and delivery as integer BDT. |
| Opportunities | Kind 1–4, title, location, eligibility, keywords, description, and a Dhaka calendar deadline. Use `applyUrl` for real postings. Demo rows use `demoDays`. |
| Products and delivery zones | Products take name, category, description, keywords, integer BDT price and integer stock. A delivery zone takes a label and integer BDT fee. |
| Orders | Reads the order reference, delivery details, price snapshots and totals. Editable status is received, confirmed, dispatched, delivered or cancelled. Cancelling a record does not automatically add its stock back. |

The reference geography, primary taxonomy, original fixture news and static policy pages are versioned with the application. Their source tables and texts remain in `reference/news`.

## 6. Three-step launch

### Step 1 — Configure Supabase

1. Create a Supabase project. In the SQL Editor, run the schema and demo files in that order.
2. In Authentication → Users, create and confirm the first administrator with an email and password. Disable public signup for a staff-only newsroom.
3. Copy `.env.example` to `.env.local` and fill the values below. Use the Supabase transaction pooler URI shown under Connect, with your database password and TLS settings. Grant the first user access with the supplied script. The command prompts for the existing account email.

```bash
nvm use
cp .env.example .env.local
npm ci
node --env-file=.env.local scripts/grant-admin.mjs
```

| Variable | Value |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase project URL |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | Supabase publishable key |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase server-only service-role key |
| `SUPABASE_DATABASE_URL` | Supabase server-only PostgreSQL transaction pooler URI |
| `NEXT_PUBLIC_SITE_URL` | Final public site origin, including HTTPS. If omitted, the request origin is used. |

### Step 2 — Verify and push to GitHub

Run these commands from the extracted project. Create an empty GitHub repository, then paste its Git remote URL when prompted.

```bash
npm run typecheck
npm run lint
npm run build
git init -b main
git add .
git commit -m 'Build BD Everyday full-stack portal'
read -r -p 'GitHub repository URL: ' github_repository_url
git remote add origin "$github_repository_url"
git push -u origin main
```

For a local production run use `npm run start`. Set the local hostname explicitly with `npm run start -- --hostname 127.0.0.1` if your execution environment restricts network interface discovery.

### Step 3 — Deploy on Vercel

Import the repository into Vercel, select Node.js 22, and add the five variables above in Project Settings → Environment Variables for the environments that need Supabase access. Use the checkout root as the project root. The bundled Vercel configuration runs `npm ci` and `npm run build`. Deploy or redeploy after setting variables. Add the eventual custom domain through Vercel and update the Supabase Auth site URL to the same origin. Open the public homepage, `/en/`, and `/admin/login`; sign in, publish a test draft, and verify the permanent article and both editions.
